# mgmt Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `mgmt`, a read-only Go CLI that joins a manager's freeform weekly markdown notes with Kubernetes-style YAML resources and reports competency gaps, open actions and review readiness.

**Architecture:** Go loads YAML and markdown, validates resources with embedded CUE, and extracts a JSON facts document from the markdown. Embedded Rego (OPA SDK) derives required competencies, statuses, gaps and report view-models, and emits `deny`/`warn` findings. Go `text/template` plus Sprig renders the view-models as markdown. A workspace can add CUE kinds, Rego policies and templates without a rebuild.

**Tech Stack:** Go (module floor `go 1.26`), `cuelang.org/go` (latest stable v0.x, not an rc), `github.com/open-policy-agent/opa/v1` (v1.21+), `github.com/yuin/goldmark` (v1.8+, GFM TaskList extension), `sigs.k8s.io/yaml` v1.6, `github.com/Masterminds/sprig/v3` v3.3, `github.com/bmatcuk/doublestar/v4` (for `**` globs). The CLI uses stdlib `flag`.

**Spec:** `docs/superpowers/specs/2026-10-21-mgmt-design.md`. Read its "Clarifications" section at the end: it fixes the worked example's dates and settles four rules.

## Global Constraints

- Module path `github.com/uatec/mgmt`; binary built from `cmd/mgmt`; `CGO_ENABLED=0` static builds for linux and darwin.
- `apiVersion` for every resource is `mgmt/v1alpha1`.
- No network access, telemetry or external calls at runtime. This covers Rego builtins and Sprig functions (see Tasks 7 and 10).
- Read only. No command writes to notes or resources. `init` creates new files only and refuses to overwrite anything; `--out` writes only the named report file.
- Deterministic: the same inputs and `--now` produce byte-identical output. Every list is explicitly sorted, and no code path reads the wall clock except the CLI's `--now` default.
- Every evidence item, action and finding that gets printed carries a `file:line` reference. Paths are slash-separated and relative to the workspace root.
- `mgmt lint` exit codes: 2 on errors; 1 on warnings with `--strict`; otherwise 0. Other commands exit 2 on errors or usage problems, otherwise 0.
- Errors block reports. Warnings never do. `<!-- mgmt:ignore id[,id] -->` suppresses warnings only.
- `mgmt lint` on 52 weekly files and 10 people completes in under 1 second.
- Dates are `YYYY-MM-DD` strings everywhere: in facts, in Rego and in output. Rego compares them lexicographically.

## Review Focus

1. **Tokens in non-prose markdown.** A `+1` inside an inline code span, a fenced code block, a URL (`https://x/@foo`), an email address (`a@b.com`) or an HTML comment must not become a token. The user expects pasted snippets and links to be ignored. Tested in Task 5.
2. **Windows line endings and BOMs.** Notes and YAML with CRLF endings or a UTF-8 BOM must give the same facts, the same line numbers and the same text, with no `\r` left in `text`. Tested in Tasks 1 and 5.
3. **Punctuation around tokens.** `+ownership,`, `(+planning)`, `+ownership.` and `+ownership:` must resolve to the bare token. The user writes prose, not syntax. Tested in Task 3.
4. **Year boundaries.** An `@3jan` written on 2026-12-29 means 2027-01-03. `2026-W53` exists, because 2026 has 53 ISO weeks. A heading `## Sam (Fri 1 Jan)` in a file dated 2026-12-28 means 2027-01-01. Tested in Task 4.
5. **Empty data.** A Person with no notes, a level with no expectations, a notes glob that matches zero files, and a cycle with no milestones must render "none" lines or omit the section. They must not crash or print `<no value>`. Tested in Tasks 10 to 12 (the `team` fixture includes Jo, who has no notes, and a cycle without milestones).

## Decisions (beyond the spec's Clarifications)

These are the builder's calls. A task that depends on one cites it by letter.

- **A. Record text.** `text` is the source line with its list marker, checkbox and blockquote marker removed, every recognised token removed (`+x -x ~x !x @x`), and any `<!-- mgmt:ignore … -->` comment removed, with whitespace collapsed and trimmed. Action `id` = lowercase hex `sha1(file + text)`.
- **B. Person context is a heading stack.** A line's person comes from the nearest enclosing heading that names a person. A heading ends the scope of every open heading at the same or a higher level. A heading that names no person sets no person of its own: at the same or a higher level it clears context, and nested lower it inherits from its parent. Every heading that names exactly one person creates a `sections` record. Tokens count toward the innermost such section.
- **C. Person matching.** A heading names a Person when it contains that Person's `metadata.name` or one of their `aliases` as a whole word, case-insensitive. Word boundaries are non-letters and non-digits, so `Jo's` matches `Jo` and `Joanne` does not. `@x` resolves dates first, then Person name or alias, then `Workspace.spec.me` (the last only inside an action, where it sets the owner to `"me"`).
- **D. Lines scanned.** The extractor blanks every masked region (fenced and indented code, code spans, autolinks, raw HTML, link destinations) in a copy of the source, then scans each line of paragraphs, list items and blockquotes. Heading lines set context and date but are not scanned for tokens. For a task-list item, only the checkbox line is the action. Its continuation lines are ordinary lines.
- **E. Tokens resolve against the line's person's framework.** If the person's framework doesn't exist, the extractor skips token resolution for that person (Rego reports `ref-unknown`). If a token is ambiguous because it's declared twice, marks using it are dropped (Rego reports `token-duplicate`). A suffix shared by two competency ids is not an error: that suffix simply doesn't resolve, and explicit tokens and full ids still do.
- **F. Inputs resolve against cycles.** `!name` resolves against the ReviewCycles that select the line's person and whose *active range* (`period.from` through the later of `period.to` and the last milestone's `due`) contains the entry date. The record gets a `cycle` field. If none match, the extractor reports `input-unknown`. If several match, it uses the first by name.
- **G. Extra error codes**, which extend the Policies table: `person-missing` (a `+`, `-`, `~` or `!` token on a line with no person), `line-multi-person` (two different `@person` tokens on one line) and `alias-duplicate` (two Persons share a name or alias, case-insensitive). YAML parse failures, an unknown `kind`, and a count of Workspaces other than one are all reported as `schema-invalid`.
- **H. A checkbox with no person** is not an action and produces no record.
- **I. Facts additions** beyond the spec's example: `sources` (`"Kind/name" → {file, line}`), `ignores` (`[{file, line, ids}]`), `options` (`{cycle}`), and `cycle` on each input record. Empty lists serialise as `[]`, never `null`.
- **J. Due dates.** A weekday name resolves to the next such day strictly after the entry date. `28oct` and `28 Oct` resolve to the first such date on or after the entry date.
- **K. Report view-models live in Rego** (package `mgmt.report`), so that Go stays limited to loading, extraction and wiring, as the spec requires. Templates only format.
- **L. Without a cycle**, the evidence settings are `minPerCompetency: 1` and `negativeOverrides: true`. `review` works without a cycle: it uses the rolling window and leaves out the inputs section.
- **M. `competency-untouched`** fires only when the person has been managed for at least the threshold (`now − since ≥ days`).

### Task 3: Token grammar

**Files:**
- Create: `internal/extract/tokens.go`
- Test: `internal/extract/tokens_test.go`

**Interfaces:**
- Produces:

```go
type RawToken struct { Sigil byte; Body string; Start, End int } // byte offsets of the whole token incl. sigil, within the line
func ScanLine(line string) []RawToken                            // sigils: + - ~ ! @
```

Rule: a sigil counts only at the start of the line or after whitespace or `(`, and only when the next character is an ASCII letter. The body is `[A-Za-z][A-Za-z0-9._-]*`, with trailing `.`, `-` and `_` trimmed (and `End` adjusted). `@` bodies may also contain spaces in exactly one case: `@28 Oct`, meaning a 1–2 digit day, one space and a 3-letter month. That case is handled by checking the next word after `@<digits>`, and it is the only case where a body can start with a digit after `@`. `@<digit>` is otherwise allowed for date forms (`@2026-10-28`, `@28oct`).

- [ ] **Step 1: Write the failing test** `TestScanLine`, table-driven on `{line, want []string}`, where each want entry is the sigil plus the body:
  - `"+ownership led the review"` → `["+ownership"]`
  - `"+ownership, -planning."` → `["+ownership", "-planning"]`
  - `"(+planning) and +delivery.ownership:"` → `["+planning", "+delivery.ownership"]`
  - `"+1 from me, -5 points, well-known, a - b"` → `[]`
  - `"x+ownership a-planning"` → `[]` (no whitespace before the sigil)
  - `"!self-assessment submitted"` → `["!self-assessment"]`
  - `"@sam draft @fri"` → `["@sam", "@fri"]`
  - `"due @28 Oct ok"` → `["@28 Oct"]`; `"@2026-10-28"` → `["@2026-10-28"]`; `"@28oct"` → `["@28oct"]`
  - `"a@b.com https://x.com/@foo"` → `[]`

### Task 5: Extractor: context and records

**Files:**
- Create: `internal/extract/index.go`, `internal/extract/extract.go`
- Test: `internal/extract/extract_test.go`, `testdata/spec-example/` (workspace: resources from the spec, plus Persons `priya` (L2) and `jo` (L3) so that the cycle selector resolves; `notes/2026-W43.md` is the spec's Notes format example byte for byte)

**Interfaces:**
- Consumes: `ScanLine`, `FileDate`/`HeadingDate`/`DueDate`, `load.Resource`, `load.NoteFile`, `facts.*`.
- Produces:

```go
type Index struct { /* person names/aliases, per-framework token map, cycles, me tokens */ }
func NewIndex(resources []load.Resource) *Index
func Extract(files []load.NoteFile, idx *Index) facts.Facts // fills Evidence, Touches, Actions, Inputs, Sections, Ignores, Diagnostics
```

  `Resources`, `Sources`, `Now` and `Options` are filled in by Task 7. Records are in file order, then line order, then token order.

The algorithm follows Decisions A–F and H. Parse each file with goldmark plus `extension.TaskList`. Build a line-start offset table to map any byte offset to a 1-based line. Blank the masked regions (Decision D), but record each `<!-- mgmt:ignore a,b -->` (on the line where it starts) before blanking HTML. Walk the top-level blocks in order, keeping a heading stack of `{level, persons []string, date}` and the current section. For each scannable line, classify its tokens:
- `+` and `-` → Evidence.
- `~` → Touch, or, on an action line, an entry in `Addresses`.
- `!` → Input.
- `@` → a date (an action's `Due` only, ignored elsewhere), else a person (attribution, and owner on an action line), else `me` on an action line.

A line is an action when its list item's first child holds a `TaskCheckBox` and the line is that item's first line. Each record increments the innermost section's `TokenCount`. Each action counts once, however many `~` tokens it has.
